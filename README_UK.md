# Переклад коментарів коду в Zed

Розширення для **macOS та Linux**, яке показує переклад коментаря мовою системи
(або мовою з `target_language`) у стандартному hover-вікні Zed. На macOS та Linux типовий провайдер —
**Google Translate** без API-ключа; якщо Google не відповідає, переклад іде через **MyMemory**.
**DeepL** працює з власним ключем API.
Підтримує **C, C++, Rust, Python, Shell Script (Bash), Swift і Dart**: рядкові, блокові
й документаційні коментарі, а також docstring Python. Рядки, сирі рядки, інтерполяція та heredoc
відрізняються від коментарів через Tree-sitter. Код у файлі не змінюється.

| Мова Zed | Коментарі | Примітки |
| --- | --- | --- |
| C, C++ | `//`, `///`, `//!`, `/* */`, `/** */`, `/*! */` | `.h` працює і в режимі C, і в режимі C++ |
| Rust | `//`, `///`, `//!`, `/* */`, `/** */`, `/*! */` | вкладені блокові коментарі |
| Swift | `//`, `///`, `/* */`, `/** */` | вкладені блокові коментарі; мову надає розширення Swift |
| Dart | `//`, `///`, `/* */`, `/** */` | вкладені блокові коментарі; мову надає розширення Dart |
| Python | `#`, docstring | shebang `#!` у першому рядку не перекладається |
| Shell Script | `#` | shebang `#!` у першому рядку не перекладається |

## Архітектура

```text
Zed → WASM-розширення → Rust LSP → Google Translate (Rust, усі платформи)
                              ↳ MyMemory (Rust, запасний для Google)
                              → DeepL (Rust, власний ключ; запасні — Google і MyMemory)
```

- `src/lib.rs` — розширення Zed, яке запускає сервер.
- `server/src/` — LSP, розпізнавання коментарів, UTF-16 координати й кеш.
- `server/src/languages.rs` — таблиця мов: languageId, розширення файлів, граматика й маркери.
- `server/src/segments.rs` — захист коду: поділ на прозу й блоки коду, мітки для коду в реченнях.
- `server/src/locale.rs` — визначення цільової мови із системної локалі.
- `server/src/google.rs` — спільний Google HTTP-клієнт на reqwest/rustls.
- `server/src/mymemory.rs` — клієнт MyMemory: поділ запитів на шматки, ліміти та помилки.
- `server/src/deepl.rs` — клієнт DeepL: читання ключа, endpoint за планом, варіанти мов, квота.
- `examples/` — налаштування Zed, гаряча клавіша та демо-файли з англійськими коментарями для кожної мови.
- `scripts/` — збірка й перевірки.

Сервер написано на чистому Rust без платформних частин, крім читання списку мов macOS, і він
збирається однаково на macOS та Linux.
Цільова мова береться із системної локалі або з `target_language` (див. [Мова перекладу](#мова-перекладу)).
Вихідна мова задається через `source_language`;
`auto` доручає визначення мови сервісу перекладу.
Якщо вихідна мова збігається з цільовою, текст повертається без змін.
Усі провайдери використовують HTTP-клієнт Rust reqwest із TLS rustls і потребують інтернету.
DeepL переходить на Google і MyMemory, а Google —
на MyMemory, якщо `fallback` не задає іншого (див. [Порядок запасних рушіїв](#порядок-запасних-рушіїв)).
До 256 успішних результатів кешуються в пам’яті; після заповнення кеш очищується.

## Збірка

На обох платформах потрібні Rust через rustup, C-компілятор для Tree-sitter і доступ
до crates.io для першого завантаження залежностей. Для Debian/Ubuntu C-компілятор
можна встановити через `sudo apt install build-essential`, на macOS — Xcode Command Line Tools.
OpenSSL не потрібен.

```sh
rustup target add wasm32-wasip2
./scripts/build.sh
```

Скрипт створює `target/release/comment-translate-lsp` і WASM-розширення. Не збирайте весь
workspace для WASM: LSP є нативним процесом. Якщо раніше було задано
`initialization_options.helper_path` або `"provider": "apple"`, видаліть їх: бекенд Apple
Translation прибрано.

## Вибір провайдера

Без поля `provider` використовується **Google**. Для Google додайте до налаштувань Zed:

```json
{
  "lsp": {
    "comment-translate": {
      "initialization_options": {
        "provider": "google",
        "source_language": "auto",
        "timeout_seconds": 60,
        "max_comment_chars": 4000
      }
    }
  }
}
```

Інші провайдери — `"mymemory"` і `"deepl"` (див. [MyMemory](#mymemory) і [DeepL](#deepl)).
Поле `target_language` описано в розділі [Мова перекладу](#мова-перекладу).
Збережіть наявне поле `binary` та інші налаштування. Після перемикання перезапустіть
мовні сервери або Zed. Приклади: [`zed-settings.json`](examples/zed-settings.json)
і [`zed-settings-google.json`](examples/zed-settings-google.json). Для Linux є
[`zed-settings-linux.json`](examples/zed-settings-linux.json): замініть шлях до сервера.

Google працює без API-ключів, але потребує інтернету та надсилає
текст коментаря Google. Використовується веб endpoint
`https://translate.googleapis.com/translate_a/single` з `client=gtx`, а не платний Cloud
Translation API. Цей вебінтерфейс може змінюватися або обмежувати частоту запитів.
HTTP 403/429, помилки мережі й некоректний JSON показуються в hover українською.
Кеш та об’єднання рядків в абзаци працюють для всіх провайдерів.

Перевірка Google через CLI:

```sh
echo '{"provider":"google","text":"Return the next counter value.","source_language":"en"}' \
  | ./target/release/comment-translate-lsp --translate
```

`--check en` повертає `network_required` для типового Google; доступ до Google перевіряйте справжнім перекладом
через `--translate` з `"provider":"google"`.

### MyMemory

[MyMemory](https://mymemory.translated.net/doc/spec.php) — безкоштовний публічний API перекладу
від Translated S.r.l. (Італія). Він не потребує ключа, і сервер звертається до нього відкрито як
`comment-translate-lsp/<версія>`. За замовчуванням MyMemory — запасний рушій для Google: якщо
Google недоступний, обмежує частоту запитів або повертає помилку, той самий абзац іде в MyMemory,
а причина записується в журнал мовного сервера. Після HTTP 429 чи 403 від Google сервер 5 хвилин
не звертається до Google і надсилає запити одразу в MyMemory, щоб не смикати сервіс, який уже
відмовляє. Кожен сервіс у ланцюжку отримує рівну частку `timeout_seconds`. Якщо не відповів
жоден, hover показує всі причини.

```json
{
  "lsp": {
    "comment-translate": {
      "initialization_options": {
        "provider": "google",
        "fallback": "mymemory",
        "mymemory_email": "you@example.com"
      }
    }
  }
}
```

- `"fallback": "none"` вимикає запасний рушій: текст коментаря тоді йде лише до Google.
- `"provider": "mymemory"` використовує MyMemory напряму, без Google.
- Без адреси MyMemory дозволяє близько 5 000 символів на день; `mymemory_email` піднімає ліміт
  приблизно до 50 000. Адреса надсилається MyMemory з кожним запитом; сервер сам її не підставляє.
- MyMemory приймає не більше 500 символів за запит, тому довший текст ділиться за рядками,
  реченнями або словами на запити до 450 байтів.
- Якість перекладу зазвичай нижча, ніж у Google. З увімкненим запасним рушієм текст коментаря
  може потрапити до другого стороннього сервісу.

Перевірка MyMemory через CLI (CLI перевіряє лише вибраний сервіс, без запасного рушія):

```sh
echo '{"provider":"mymemory","text":"Return the next counter value.","source_language":"en"}' \
  | ./target/release/comment-translate-lsp --translate
```

### DeepL

[DeepL](https://www.deepl.com/pro-api) — необов’язковий провайдер із власним ключем API; план
DeepL API Free має місячну квоту символів, і перевірка через CLI нижче показує вашу. З `"provider": "deepl"` порядок такий:
DeepL → Google → MyMemory, як у плагіні перекладу Omarchy.

```json
{
  "lsp": {
    "comment-translate": {
      "initialization_options": {
        "provider": "deepl",
        "deepl_key_file": "~/.local/state/omarchy/translate-deepl.key"
      }
    }
  }
}
```

- Ключ ніколи не зберігається в налаштуваннях Zed: сервер читає його з `deepl_key_file`
  (початкове `~/` розгортається) або, без цього поля, зі змінної оточення `DEEPL_AUTH_KEY`. Файл
  ключа, збережений плагіном перекладу Omarchy, підходить без змін. Тримайте файл закритим
  (`chmod 600`).
- Ключі із закінченням `:fx` (план Free) йдуть на `api-free.deepl.com`, інші — на `api.deepl.com`,
  як JSON POST із ключем у заголовку `Authorization`, ніколи в адресі чи журналі. Журнал показує
  лише план або причину, чому DeepL пропускається.
- Ключ читається один раз під час запуску сервера; після зміни перезапустіть мовний сервер.
- Без ключа DeepL пропускається, і перекладає наступний сервіс. Після HTTP 403 (ключ відхилено),
  429 чи 456 (вичерпано місячну квоту) DeepL пропускається на 5 хвилин.
- Для англійської та португальської DeepL потребує варіанта: `en-GB` чи `pt-PT` у
  `target_language` вибирає британську англійську чи європейську португальську, інакше
  використовуються американська й бразильська.
- Текст коментаря надсилається DeepL SE (Німеччина).

Перевірка ключа й використання квоти через CLI:

```sh
echo '{"provider":"deepl","operation":"check","deepl_key_file":"~/.local/state/omarchy/translate-deepl.key"}' \
  | ./target/release/comment-translate-lsp --translate
```

`"status":"ready"` приходить разом із `plan`, `character_count` і `character_limit`.

### Порядок запасних рушіїв

`fallback` задає сервіси, які пробуються після провайдера, по черзі: `"none"`, назва одного
провайдера або список, наприклад `["google", "mymemory"]`. Без поля DeepL переходить на Google і
MyMemory, Google — на MyMemory, а MyMemory — нікуди. Список не може містити сам провайдер чи
повтори. Порядок записується в журнал мовного сервера під
час запуску. Наприклад, `"provider": "deepl", "fallback": ["mymemory"]` ніколи не надсилає
коментарі Google.

## Мова перекладу

Поле `target_language` в `initialization_options` задає мову перекладу кодом BCP 47:
`"uk"`, `"en"`, `"de"`, `"pl"`, `"zh-Hans"`, `"zh-Hant"` тощо. Регістр і `_` замість `-`
не мають значення: `uk_UA` стає `uk-UA`.

```json
{
  "lsp": {
    "comment-translate": {
      "initialization_options": {
        "target_language": "de"
      }
    }
  }
}
```

Якщо поле відсутнє або дорівнює `"auto"`, мова береться із системи під час запуску LSP:

- macOS: перша мова зі списку **Системні параметри → Загальні → Мова й регіон**
  (`defaults read -g AppleLanguages`), потім змінні оточення;
- Linux: `LC_ALL`, `LC_MESSAGES`, `LANG` у порядку пріоритету POSIX; непорожній список
  `LANGUAGE` (наприклад `uk:en`) має перевагу, крім локалі `C`/`POSIX`;
- якщо мову не визначено (наприклад, `LANG=C.UTF-8`), використовується англійська.

Регіон локалі не впливає на переклад (`uk_UA.UTF-8` → `uk`), але для китайської
зберігається письмо: `zh_TW` → `zh-Hant`, `zh_CN` → `zh-Hans`. Вибрана мова та її джерело
записуються в журнал мовного сервера (у палітрі команд Zed — `open language server logs`).
Після зміни `target_language` або системної мови перезапустіть мовні сервери або Zed.
Заголовок підказки показує код мови: `Переклад → uk`. Повідомлення про помилки
залишаються українською.

## Підключення до Zed

1. Виконайте `./scripts/build.sh`.
2. У палітрі Zed виконайте `zed: install dev extension` і виберіть корінь проєкту.
3. Додайте потрібні поля з [`examples/zed-settings.json`](examples/zed-settings.json)
   в особисті налаштування Zed. Перевірте абсолютний шлях до LSP.
4. Після зміни `initialization_options` перезапустіть мовні сервери або Zed.
5. Відкрийте файл підтримуваної мови, наведіть на коментар або поставте курсор усередину
   коментаря та викличте `editor: hover`. Приклад гарячої клавіші `ctrl-alt-t` наведено
   в [`examples/keymap.json`](examples/keymap.json).

Основні сервери мов (`clangd`, `rust-analyzer`, `basedpyright` тощо) працюють як раніше:
Zed запускає `comment-translate` поряд із ними через типове значення
`"language_servers": ["..."]` і об’єднує їхні hover. Якщо для мови задано власний список
`language_servers` без `"..."`, додайте до нього `"comment-translate"`.
Swift і Dart з’являються в Zed лише після встановлення розширень Swift і Dart.
Поза коментарями перекладач не викликається.
Для англомовного коду можна встановити `"source_language": "en"`: визначення мови
дуже коротких коментарів може бути неточним. Типове значення — `auto`.

## Заголовки C (`.h`)

Zed типово відкриває `.h` у режимі **C++**. Сервер зареєстровано і для C, і для C++,
тому коментарі в заголовках перекладаються без асоціації `file_types`. Якщо проєкт
перемикає `.h` на **C** через `file_types`, переклад теж працює.

## Перевірки

```sh
cargo fmt --all --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo build -p comment-translate-lsp
python3 scripts/smoke_test.py
python3 scripts/test_cli.py target/release/comment-translate-lsp
```

Smoke test використовує справжній LSP з однаковою вихідною й цільовою мовою, тому не потребує
мережі. Перевіряє `.c`, `.h` у режимах C і C++, Rust, Python,
Shell Script, ігнорування непідтримуваних мов, hover, редагування, закриття,
ліміти й завершення процесу. Rust-тести для кожної мови перевіряють типи вузлів коментарів,
маркери всередині рядків, групування рядків, docstring, shebang і UTF-16 координати. Rust-тести
окремо перевіряють кешування, помилки, тайм-аут, ланцюжок запасних рушіїв і захист коду.
`test_cli.py` перевіряє `--check` і `--translate` без мережі. Rust-тести перевіряють Google,
MyMemory і DeepL: кодування параметрів, JSON і HTTP-помилки. Два loopback HTTP-тести
позначені `ignored`, оскільки потребують дозволу створювати локальні TCP-сокети:

```sh
cargo test -p comment-translate-lsp -- --include-ignored
```

Linux CI запускає ці перевірки, збирає сервер і WASM, перевіряє CLI та LSP.
Звичайні тести не потребують інтернету. Справжній переклад потребує доступу до Google, MyMemory
або DeepL.

## Захист коду

Перекладач отримує лише прозу; код до нього не потрапляє.

- **Блоки коду** — огородження Markdown (```` ``` ````, `~~~`), Doxygen `@code … @endcode`,
  `\code … \endcode` і `@verbatim … @endverbatim`, приклади doctest Python (`>>>` до
  наступного порожнього рядка) — показуються дослівно й не надсилаються на переклад. Абзаци
  прози навколо них перекладаються й кешуються окремо.
- **Код у реченнях** перед перекладом замінюється мітками `x0_`, `x1_`, … (`x0_()` для виклику функції,
  щоб DeepL не читав його як номер телефону), а після перекладу
  повертається: код у зворотних лапках, ідентифікатори, схожі на код (`next_value()`,
  `MAX_SIZE`, `nextValue`, `HashMap`, `std::mem::swap`, `node->next`), URL, команди Doxygen з
  назвою параметра (`@param[in] node`) і поля reST (`:param count:`). Звичайні слова, `item(s)`
  та адреси пошти не змінюються. Мітки, схожі на ідентифікатор, зберігають контекст: Google
  перекладає «Call x0_» як виклик функції, а з `⟦0⟧` обирав «Зателефонуйте».
- **Якщо перекладач загубив, змінив або повторив мітку**, абзац перекладається повторно без
  міток, як раніше. Абзац, у якому поза кодом немає слів, не надсилається взагалі.

Документаційні коментарі Rust, Swift і Dart (`///`, `//!`, `/** */`, `/*! */`) пишуться в
Markdown, тому їхній hover показується як Markdown: блоки коду підсвічуються (блок без мови
отримує мову документа), а переноси рядків зберігаються. Звичайні коментарі та інші мови
показуються як текст, тому `*` і `_` у них не перетворюються на форматування.

## Обмеження

Підтримуються C, C++, Rust, Python, Shell Script, Swift і Dart на macOS та Linux.
Інші мови ігноруються: hover для них не з’являється.
Мова визначається за `languageId` від Zed, а якщо він невідомий — за розширенням файлу.
Сусідні рядкові коментарі (`//`, `///`, `//!` або `#`) без коду перед маркером
перекладаються одним блоком. Порожній рядок, код або блоковий коментар відокремлює блоки.
Порожній коментар `//` чи `#` усередині блоку зберігає розділення абзаців. Перед перекладом
рядки всередині абзацу з’єднуються пробілами; межі абзаців зберігаються як подвійний перенос.
Пункти списків (`1.`, `1)`, `-`, `*`, `+`, `•`) та Doxygen-теги (`@brief`, `@param`,
`@return`, також форма `\param`) залишаються окремими рядками. Перенесений опис пункту
з’єднується пробілами, а відступи вкладених пунктів зберігаються. Заголовки Markdown
(`# Examples`) і поля reST (`:param x:`) залишаються окремими рядками; блоки коду зберігаються
дослівно (див. [Захист коду](#захист-коду)). У вкладених коментарях Rust, Swift і Dart
прибираються лише зовнішні `/*` та `*/`. Docstring Python — лише перший рядковий літерал
модуля, класу чи функції без префіксів `f`/`b`/`t`; лапки й префікси `r`/`u` прибираються,
відступи вирівнюються як в `inspect.cleandoc`. Інші рядки, f-рядки, heredoc і shebang
не перекладаються. Усе це відбувається перед передачею тексту обраному перекладачу. Одночасно працює
один запит перекладу; запити й очікування черги обмежуються `timeout_seconds`, а за тайм-ауту
поточний запит скасовується.
Власної команди перекладу немає: використовується стандартний hover Zed, тому переклад
може запускатися й наведенням миші. Автоматичного встановлення нативних програм немає.

Документація: [розширення Zed](https://zed.dev/docs/extensions/developing-extensions),
[DeepL API](https://developers.deepl.com/docs), [MyMemory API](https://mymemory.translated.net/doc/spec.php).
